# 早起きくん 手動QAチェックリスト

対象: `docs/designs/hayaoki-app.md`（T1〜T14、全実装済み・main merge済み）
自動テストが担当するのはstore内の純関数のみ（3A方針）。画面・打刻フローは本チェックリストで人間が確認する。

## 使い方

- 上から順に実施する。多くのステップは直前のステップの状態に依存する。直前以外の依存がある場合は「（要: n）」と明記した。
- 打刻・取り消しは1日1回しかできない不可逆操作なので、⚠️の付いたステップは特に順番を守ること。
- 「起きたよ！」ボタンは実際の端末時計を見て04:00〜12:00の判定をする。時間帯外でテストする場合はセクション0-Bの端末時計変更テクニックを使う。
- 事前に一度も打刻していない、まっさらな状態（初回インストール、またはAsyncStorageが空）から始めるのが望ましい。既存データが残っていると「未記録」を前提にしたステップが噛み合わなくなる。

---

## 0. 準備

- [ ] 0-1. `npm install` 済み、`npx expo start` が起動し、実機またはExpo Goで開ける
- [ ] 0-2. 親確認PINの初期値は `0000`（未設定時のデフォルト）であることを把握している
- [ ] 0-3. まっさらな状態で開始する（望ましい）。既存データがある場合は、以降の「未記録」前提のステップは参考程度に読み替える

**0-B. 端末時計を使った時間帯テクニック（複数日にまたがる確認をまとめて行う場合に使用）**
このアプリは打刻可否・目標時刻ロック・ストリーク計算のすべてを「実際の端末の現在時刻」から判定する（テスト用の日付注入口はない）。そのため：
- 04:00〜12:00外の挙動を確認したい → 端末の日付/時刻設定でその時間帯に変更し、アプリをフォアグラウンドに戻す（自動で再評価される）
- 複数日ぶんのストリークを1回のQAセッションで確認したい → 端末の日付を1日ずつ進めて打刻を繰り返す
- 確認後は必ず端末時計を実際の日時に戻すこと

## 3. 週間スケジュール編集の基本動作（要: 2-2でロック解除済み）

今日の曜日以外の行で確認する（今日の曜日は後述セクション5・6で扱うため、ここでは触らない）。

- [ ] 3-1. 7行すべてがデフォルトでON、目標時刻07:00になっている
- [ ] 3-2. 今日以外の曜日を1つ選びOFFに切り替える → 時刻表示が「－」のグレー表示に変わる → 「保存」をタップ → 「保存しました」と表示される
- [ ] 3-3. 同じ行を再度ONに戻し「保存」 → 再編集できることを確認する
- [ ] 3-4. 別の（今日以外の）曜日の時刻部分をタップ → ネイティブタイムピッカーが開く → 例えば06:30を選択 → 「保存」 → 行の表示が06:30に変わり「保存しました」と表示される
- [ ] 3-5.（任意）ピッカーで04:00〜12:00の範囲外（例: 13:00）を選べる端末であれば選択して保存 → 「目標時刻は04:00〜12:00の範囲で入力してください」と表示され保存されない。ピッカーがそもそも範囲外を選ばせない端末の場合はスキップしてよい

## 4. 今日の曜日の目標時刻を確認・調整する（要: セクション3。まだ打刻していない状態で行うこと）

打刻前に、今日の目標時刻をテストしやすい値にしておく。

- [ ] 4-1. 今日の曜日の行がまだロックされていない（グレーアウトしていない）ことを確認する
- [ ] 4-2. 目標時刻を「今すぐより少し後（例: 2〜3分後）」に設定して保存する → 「達成」を狙うテストがしやすくなる。あるいは「今すぐより前」に設定すれば「遅刻」を狙える。どちらを先に試すかは後続ステップで選べる

## 5. ⚠️ 今日の曜日をOFFにした場合の打刻ブロック確認（要: セクション4、まだ打刻していないこと）

このテストは打刻前にしかできない（打刻後は目標ロックによりOFFへの変更ができなくなる）。

- [ ] 5-1. 今日の曜日をOFFに切り替えて保存する → 「保存しました」
- [ ] 5-2. 「今日」タブへ移動 → キャラクターは😌、ボタンは無効（グレー）、理由テキストに「本日は目標が設定されていません」と表示される
- [ ] 5-3. 「カレンダー」タブへ移動 → 今日のセルが枠なし・グレー・記号なし（目標なし状態）で表示される
- [ ] 5-4. 「設定」タブに戻り、今日の曜日を再度ONに戻し、目標時刻を再設定（セクション4-2の値）して保存する → 「今日」タブでボタンが有効に戻ることを確認する

## 6. ⚠️ 打刻フロー（要: セクション4で目標時刻を設定済み、打刻はこの1回のみ行う）

現在時刻が04:00〜12:00の範囲内であることを確認してから行う（範囲外なら0-Bのテクニックで時間帯を合わせる）。

- [ ] 6-1. 「今日」タブで、打刻前の状態を確認する：キャラクター😴、ポイント: 0（初回データなしの場合）、連続達成: 0日、励ましメッセージなし、ボタンが緑色で有効
- [ ] 6-2. 「起きたよ！」ボタンをタップする
- [ ] 6-3-A.（目標時刻より前にタップした場合）キャラクターが😄に変わる、ポイントが+2される、連続達成が1日になる、「はじめての早起き達成、やったね!🎉」メッセージが表示される、ボタンが無効（グレー）になり理由が「本日はすでに記録済みです」になる
- [ ] 6-3-B.（目標時刻より後にタップした場合）キャラクターが😥に変わる、ポイントは0のまま、連続達成は0日のまま、「今日はちょっと遅かったね。また明日がんばろう!」メッセージが表示される、ボタンが無効になる
- [ ] 6-4. もう一度ボタンをタップ（無効状態）→ 反応しない、記録が増えない、クラッシュしない
- [ ] 6-5. 「カレンダー」タブへ移動 → 今日のセルが、達成なら緑・実線枠・✓、遅刻なら橙・破線枠・△で表示される
- [ ] 6-6. 「設定」タブへ移動 → 今日の曜日の行がグレーアウト（ロック）され、スイッチ・時刻編集ができないことを確認する。他の曜日の行は編集可能なままであることも確認する（T9の曜日別ロック修正の確認）

## 7. ⚠️ 親による記録の取り消し（要: セクション6で打刻済みであること）

- [ ] 7-1. 「設定」タブの一番下に「本日の記録の取り消し」セクションが表示され、現在の記録（達成/未達成と打刻時刻）が表示されていることを確認する
- [ ] 7-2. 「取り消す」をタップ → 確認ダイアログ「本日の記録を取り消しますか？」が表示される（キャンセル / 取り消す の2択）
- [ ] 7-3. 「キャンセル」を選ぶ → 何も変わらず記録は残ったまま
- [ ] 7-4. 再度「取り消す」→ 今度はダイアログの「取り消す」（破壊的操作の赤系ボタン）を選ぶ → 「取り消しました」という確認アラートが表示される
- [ ] 7-5. アラートを閉じる → 「本日の記録の取り消し」セクションが画面から消える（取り消し済みのため）
- [ ] 7-6. 「今日」タブへ移動 → キャラクターが😴に戻る、ポイントが取り消し前の分だけ減っている、連続達成が0日に戻る、励ましメッセージが消えている、ボタンは無効のまま、理由テキストが「本日の記録は取り消されました（再打刻はできません）」に変わっている
- [ ] 7-7. ボタンが無効であることを再確認し、万一有効化されていても再打刻できないことを確認する（再打刻拒否は打刻ボタンの無効化とストア側の重複ガードの二重防御）
- [ ] 7-8. 「カレンダー」タブへ移動 → 今日のセルが灰色・点線枠・「・」（未記録）表示に戻っている
- [ ] 7-9. 「設定」タブへ移動 → 今日の曜日の行のロックが解除され、再度編集可能になっていることを確認する（取り消し後は当日ロックも解除される仕様）

## 8. 複数日にまたがる確認（要: セクション6・7が完了していること。実際に日をまたぐか、0-Bの端末時計テクニックを使う）

このセクションは1週間かけて自然に確認してもよいし、QAセッション内で端末時計を1日ずつ進めて圧縮確認してもよい。

- [ ] 8-1. 2日目：今日の曜日がONであることを確認し、目標時刻より前に打刻 → キャラクター😄、連続達成2日、メッセージは「今日も早起きできたね!」（初回達成・3日・7日のいずれでもない通常メッセージ）
- [ ] 8-2. 3日目：同様に目標時刻より前に打刻 → 連続達成3日、メッセージが「3日連続達成中!すごい!」に変わる
- [ ] 8-3.（要: 8-1〜8-2で連続達成中）ある日にわざと目標時刻より後に打刻（遅刻）→ 連続達成が0日に戻る、メッセージが「連続記録はここまで。また今日から積み重ねよう!」（streak-broken、初回未達成メッセージより優先される）
- [ ] 8-4. 新たに7日連続で目標時刻より前に打刻を続ける → 7日目に連続達成7日、メッセージが「7日連続達成!早起き名人だね!」になる
- [ ] 8-5.（任意・端末時計テクニック推奨）過去に打刻・達成した日の曜日設定を後から変更（例: その曜日をOFFにする）→ カレンダーで過去の達成日の表示が変わらない（遡及的に再分類されないことの確認。T4の変更履歴機能）

## 11. 対象外・自動テストに委ねている項目（参考・手動確認不要）

以下は本チェックリストの対象外。理由とともに記載する。

- AsyncStorage書き込み失敗時の挙動（トースト表示・UI据え置き） → `store/useAppStore.test.ts` で自動テスト済み
- 破損JSONからの起動復旧（空ストアへのフォールバック） → `store/persistence.test.ts` で自動テスト済み
- 重複打刻ガード・秒単位の達成判定・OFF日を挟んだストリーク計算・当日ロックの詳細分岐 → `store/entries.test.ts` / `store/schedule.test.ts` で自動テスト済み（3A方針）
- タイムゾーンをまたいでも日付がずれないこと（UTC変換を使わない実装） → `store/dateUtils.test.ts` で自動テスト済み
