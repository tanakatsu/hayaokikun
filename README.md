# 早起きくん

子ども向けの起床習慣化アプリ。Expo（React Native）製で、子ども自身のスマホ/タブレットにインストールして使う。曜日ごとに目標起床時刻を設定し、子どもが朝起きて「起きたよ！」ボタンを押すと打刻され、達成状況がカレンダーとポイントで可視化される。

個人・家族利用のみを想定したMVP（アカウント不要・完全オフライン・ストア配信なし）。設計の背景や意思決定の詳細は [`docs/designs/hayaoki-app.md`](docs/designs/hayaoki-app.md) を参照。

## 使い方

アプリには「今日」「カレンダー」「設定」の3つのタブがある。子どもが毎朝使うのは「今日」タブだけで、「設定」タブは保護者用。

### はじめに（保護者）

1. 子どもの端末にアプリをインストールして起動する（インストール方法は後述の「動作検証」を参照）
2. 「設定」タブを開き、PIN `0000` を入力してロックを解除する
3. 曜日ごとに目標起床時刻（05:00〜08:00）を設定し、行ごとに「保存」を押す。起きなくてよい曜日はスイッチをOFFにする
4. 設定が終わったら「🔒 ロックする」を押して子どもが触れないようにしておく

初回起動時は全曜日が「ON・06:30」で始まる。

**注意**: PINは `0000` 固定で、現時点ではアプリ内から変更できない。変えたい場合はソースを書き換えて再ビルドする（後述の「設定値の変更」を参照）。

### 毎朝の流れ（子ども）

1. 起きたらアプリを開き、「今日」タブの「起きたよ！」ボタンを押す
2. 押した時刻が目標時刻以前なら「達成」、過ぎていたら「未達成（遅刻）」として記録される
3. 画面の顔マーク・ポイント・連続達成日数・励ましメッセージが更新される

ボタンが押せない（灰色の）ときは、ボタンの下に理由が表示される:

| 表示 | 意味 |
|---|---|
| 打刻できるのは05:00〜08:00の間だけです | 打刻できる時間帯の外。この時間帯を過ぎるとその日は記録できない |
| 本日は目標が設定されていません | その曜日がOFFになっている |
| 本日はすでに記録済みです | 打刻は1日1回だけ |
| 本日の記録は取り消されました | 保護者が取り消した日。子ども側からは再打刻できない |

### ポイントと連続達成

- **ポイント**: 「達成」した日1日につき1ポイント。現時点では貯まるだけで、使い道はアプリ上では決めていない（ご褒美との交換などは家庭のルールで）
- **連続達成**: 今日から遡って「達成」が続いている日数。OFFの曜日は飛ばして数えるので、休日を挟んでも途切れない。「未達成」または「未記録」の日があると0に戻る
- 初めての達成・3日連続・7日連続などの節目で、特別な励ましメッセージが出る

### カレンダーで振り返る

「カレンダー」タブで月ごとの記録を確認できる。打刻した日は時刻も表示される。色だけでなく枠線の種類でも区別できるようになっている。

| 表示 | 意味 |
|---|---|
| 緑・実線 | 達成 |
| オレンジ・破線 | 未達成（遅刻） |
| 薄い灰色・点線 | 未記録（目標があったのに打刻しなかった日） |
| 灰色・枠なし | 目標なし（OFFの曜日、アプリを使い始める前の日） |
| 青い太枠 | 今日 |

### 記録の修正（保護者）

打刻を忘れた、押し間違えたといったときは、「設定」タブ下部の「直近の記録の修正」から直せる。対象は今日から7日前までの8日間。

- **追加**: 打刻がない日に時刻を入れて記録する（例: 起きていたのに押し忘れた日）
- **時刻を変更**: 記録済みの時刻を直す。子どもが押した元の時刻は「親が修正（元 06:12）」のように残る
- **取り消す**: 記録を「未記録」に戻す。時刻を入れ直せば元に戻せる

保存前に確認ダイアログで「達成／未達成」のどちらになるかが表示される。入力できるのは05:00〜08:00の範囲で、今日の分は現在より前の時刻のみ。

### 目標時刻を変更するとき

- 変更は保存した日から有効になり、過去の記録の判定は変わらない（打刻した時点の目標時刻で判定が固定される）
- その日にすでに打刻済みなら、今日の曜日の行はロックされて変更できない。翌日以降に変更すれば、次の同じ曜日から反映される

### データについて

- 記録はすべて端末の中だけに保存される。インターネット接続やアカウントは不要
- バックアップ機能はないため、アプリの削除・端末の初期化・機種変更をすると記録は消える

## 必要なもの

- Node.js（`npx expo`が動くバージョン）と npm
- 動作確認用の実機（Android/iOS）に [Expo Go](https://expo.dev/go) アプリ、またはPCにAndroid Studio/Xcodeのシミュレータ
- スタンドアロンビルドを試す場合は [Expo](https://expo.dev/) アカウント（EAS Buildを使う。詳細は後述）

## 動作検証

このアプリの主要な判定（打刻有効時間帯 05:00〜08:00、目標時刻との比較、曜日ON/OFF、ストリーク計算）はすべて「実際の現在時刻」に基づく。そのため検証方法を目的に応じて使い分ける。

| 検証方法 | 向いている用途 | 制約 |
|---|---|---|
| 自動テスト（`npm test` / `npm run test:e2e`） | ロジックとUIフローの回帰確認。日をまたぐシナリオも仮想時刻で一瞬で検証できる | 実機固有の挙動（保護者アプリのブロック）は検証できない |
| Expo Go | 開発中の素早い動作確認 | 保護者アプリ（スクリーンタイム管理）のブロック挙動は、スタンドアロンビルドと異なる可能性がある（バンドルIDが別のため） |
| Preview build（EAS Build） | 実機配布前の最終確認。実際に子どもが使うのと同じ形（保護者アプリ含む）で確認できる | ビルドに数分〜十数分かかる。iOSは有料のApple Developer Program登録が必要 |

### 自動テスト

```bash
npm test        # 単体テスト（store配下の純関数：打刻判定・ストリーク計算・永続化など）
npx playwright install chromium  # E2Eテストの初回のみ（Playwrightのブラウザ本体をインストール）
npm run test:e2e  # E2Eテスト（Playwright、react-native-web上で実行。画面操作・複数日シナリオを検証）
```

`test:e2e`は`expo start --web`を自動起動してブラウザ上のJS時刻を仮想化するため、実際に日をまたがずに「複数日連続達成」「曜日設定の有効開始日」などのシナリオを検証できる。詳細は [`e2e/`](e2e/) 以下と `playwright.config.ts` を参照。どちらもCI/CDには組み込まず、ローカル実行のみを想定している。

### Expo Goでの動作検証

1. `npm run start` を実行し、表示されたQRコードを子どもの端末のカメラ（iOS）またはExpo Goアプリ（Android）で読み込む
2. 初回は完全に打刻していない、まっさらな状態（AsyncStorageが空）から始めるのが望ましい
3. 05:00〜08:00外の挙動やストリークなど、複数日にまたがる確認をしたい場合は端末の日付/時刻設定を変更してアプリをフォアグラウンドに戻す（このアプリにテスト用の日付注入口はなく、実際の端末時計を見て判定する）。確認後は必ず端末時計を実際の日時に戻すこと
4. 画面ごとの詳細な確認手順は [`docs/qa/manual-test-checklist.md`](docs/qa/manual-test-checklist.md) のチェックリストに従う

**注意**: Expo Goはバンドル ID が異なるため、保護者アプリ（スクリーンタイム管理など）による早朝時間帯のブロック確認は、スタンドアロンビルドと異なる場合がある。最終確認したい場合は下記のPreview buildを使う（なお、ローカル通知機能はAndroid版Expo Goでのクラッシュが原因で削除済み。`docs/qa/manual-test-checklist.md`参照）。

### Preview buildでの動作検証（EAS Build）

Expo Goでは確認できない、実機にインストールした状態そのもの（保護者アプリのブロック挙動など）を確認したいときに使う。

ビルド設定（`eas.json`）はリポジトリに含まれており、`development` / `preview` / `production` の3プロファイルが定義済み。初回はExpoアカウントでログインだけしておく:

```bash
npx eas-cli login  # Expoアカウントでログイン
```

**フォークして自分のアカウントでビルドする場合**: `app.json` の `extra.eas.projectId` は作者のExpoプロジェクトを指しているため、そのままではビルドできない。`extra.eas` ブロックを削除してから `npx eas-cli init` を実行し、自分のプロジェクトIDを割り当てる。あわせて `android.package`（`com.tanakatsu1080.hayaokikun`）も自分用の値に変えておく。

ログインできたら、`preview`プロファイルでビルドする:

```bash
npx eas-cli build --platform android --profile preview  # APKが生成される。ビルド完了後のURLからそのまま端末にインストール可能
npx eas-cli device:create                                 # iOSのみ・初回: 子どもの端末のUDIDを登録（プロビジョニングプロファイルに含めるため必須）
npx eas-cli build --platform ios --profile preview        # 要Apple Developer Program登録（有料・年次更新）
```

- Android: ビルド完了後にEASが発行するURLを子どもの端末で開き、APKを直接インストールする。追加コストなし
- iOS: `eas device:create`で事前に端末を登録していないと、ビルドしても実機にインストールできない（プロビジョニングプロファイルの対象外になるため）。また無料のApple IDだけでは恒久的なスタンドアロンインストールができない（7日で失効し再署名が必要）ため、Apple Developer Program（有料）への登録が実質必須
- どちらの場合も、インストール後は「0. 準備」からの手動QAチェックリスト（[`docs/qa/manual-test-checklist.md`](docs/qa/manual-test-checklist.md)）を一通り流し、特に保護者アプリのブロック確認を重点的に見る

対象OS・配布方針の詳細な検討経緯は設計書の [Distribution Plan](docs/designs/hayaoki-app.md#distribution-plan) を参照。

## 設定値の変更（`store/config.ts`）

打刻できる時間帯やPINなど、家庭ごとに変えたくなりそうな値は [`store/config.ts`](store/config.ts) にまとまっている。アプリ内の設定画面からは変えられないため、このファイルを書き換えてアプリを再ビルド（Expo Goなら開発サーバーを再起動）する。

| 定数 | 既定値 | 意味 |
|---|---|---|
| `MIN_TARGET_TIME` | `'05:00:00'` | 打刻できる時間帯の開始時刻。目標時刻・保護者による修正時刻の下限も兼ねる |
| `MAX_TARGET_TIME` | `'08:00:00'` | 打刻できる時間帯の終了時刻（この時刻ちょうどまで打刻可）。目標時刻・修正時刻の上限も兼ねる |
| `DEFAULT_TARGET_TIME` | `'06:30:00'` | 初回起動時に全曜日へ設定される目標時刻 |
| `DEFAULT_PARENT_PIN` | `'0000'` | 設定タブを開くためのPIN |
| `PARENT_EDIT_WINDOW_DAYS` | `7` | 保護者が記録を修正できる日数。今日に加えて何日前まで遡れるか |

変更するときの注意:

- 時刻は必ず `'HH:MM:SS'`（24時間表記、ゼロ埋め）で書く。文字列の大小比較で判定しているため、`'5:00:00'` のように書くと正しく動かない
- `MIN_TARGET_TIME` は `MAX_TARGET_TIME` より前、`DEFAULT_TARGET_TIME` はその2つの間に収める
- `DEFAULT_TARGET_TIME` が効くのは初回起動時だけ。すでに使っている端末の目標時刻は変わらないので、設定タブから変更する
- `DEFAULT_PARENT_PIN` を変えると、すでに使っている端末のPINも変わる（アプリ内でPINを保存する画面がまだなく、常にこの値が使われるため）
- 時間帯を変えても、過去の記録の達成／未達成は変わらない（打刻時点の目標時刻で判定が固定される）
- 単体テスト・E2Eテスト・手動QAチェックリスト（`docs/qa/manual-test-checklist.md`）は既定値を前提に書かれている。値を変えるとテストが落ちるので、必要に応じてテスト側の時刻も合わせる

上の「使い方」に書いた時刻・PIN・日数は、すべてこの既定値での説明。

## 主な制約（詳細は設計書参照）

- 対象は子ども1人・単一端末での利用を想定。アカウント機能・クラウド同期はなし
- データはAsyncStorageのみに保存。端末紛失・初期化で履歴が失われるリスクを許容している
- ポイントの使い道（スマホ使用時間への変換など）は未定義。増減を表示するのみ
